## 3. 本轮真改了什么（都能被断言）

1. **接 main 的 26 个提交**（`git merge origin/main`，**零冲突**）：D24/D25/D26、#114/#116/#117/#121/#125/#126 等。
2. **修一个真缺陷（GJ-CAP-22 名不副实）**：`Capabilities()` 把 `GJ-CAP-22 StartupSelfCheck` 标 `Implemented=true`，但 `New` 只做「配置校验 + 编公开路径 + 打印清单」，**没有拉 JWKS**；而契约 §5.1「构造」步与 §2.1 的表（`:131`/`:162`）写死「校验必填项、**拉 JWKS**、打印放行清单」，Java `GuanjinStartupChecker.check()` 也是 `jwks.refresh()` 失败即抛。

### P0-1 · `alg` 三方矛盾（合入阻断，**需 spencer 拍方向**）

- **事实链（我自己核过源码，非转述）**：
  - 平台签发侧写死 `alg="SM2"`：`cmd/guanjind/keygen.go` 的 `gateway-v1 → signing.AlgSM2`（"SM2"）+
    `migrations/000013` 的 `signing_keys_purpose_algo CHECK (purpose='gateway' AND algorithm='SM2')` +
    `internal/signing/signing.go:212` `SignJWT` 把 `k.Algorithm` **原样写进 JWS header**；
  - 契约 M2（`sdk-contract.md §4.1`）、Java `JwksKey.ALG`、Go `SigningAlg` 都要求 **"SM3withSM2"**；
  - 我方 SDK 对非 SM3withSM2 一律拒（`TestVerifyRejectsTamperedAndBadAlg`）。
- **后果**：真机链路 100% 401（"alg 必须是 SM3withSM2，得到 "SM2""）；Java 侧更糟——`JwksSet.gatewayKeys()`
  按 alg 过滤，真 JWKS 的网关键会被筛掉。**"S9 最小接入跑通"目前只在自签回路成立**
  （example 自签自验；`internal/gateway/testsupport_test.go` 造 key 行用的是 `AlgSM3WithSM2`，没走 DB CHECK）。
- **处置二选一（都不是我该单边拍的）**：①平台改 `keygen.go` + 000013 CHECK → `SM3withSM2`
  （触及迁移与 Core 树）；②M2 改 `SM2` 连带双 SDK + 契约（属判据/契约变更）。
  **落账前不合**；方向定了 Go 侧还要补 `ParseJWKS` 按用途过滤 + `KeyCount` 只数网关键。
