## 3. 为什么平台侧判重在语义上不成立

- 平台是**签发方**：每条断言的 `jti` 都是它**刚生成的新 UUID**。平台侧判重判的是自己刚写出的值，**正常流量永不命中**，只有构造用例才能"证"出第二次 401——那证明的是测试夹具，不是生产行为。
- 按 **`decisions.md` D10 六步时序**，断言的「**读**」发生在**验签方**（①读原始头 → ②验签 → ③claim 校验…）；平台**永远不接收**断言，要求它查重等于要求它处理一个**永不收到的输入**。
- 代价侧：若真按"平台判重"实现，需要每条转发请求一次 Redis `SET NX PX` 写（数据面热路径），且 Redis 不可用时按 fail-closed 会把整个数据面打成 503——为一个**不可能发生**的事件付热路径 + 可用性代价。

## 4. 落地与守线（防回退）

- **Edge（`#54`）**：撤掉平台侧 `jti` 判重（`replay.go` / `adapter/replay.go` / `pipeline` ④′ / `cmd/guanjingw` 的 Redis 客户端），改为签发面三条举证（两个不同 `jti` 且 `exp-iat==60` / 假上游自己判出 401、网关逐字节透传 / `replay-window` 过期后 200）。
