# `authz.enabled` 默认值与「缺 `AuthzModel` bean 即启动失败」的裁定（2026-11-10）

> **性质**：基线**释义 + 执行形态**记录，**不是**契约变更、**不是**判据变更。裁定人 = **Spec**（基线释义负责人）；入库转录 = Ark（2026-11-10）。路径固定为 `notes/sdk-authz-enabled-默认-2026-11-10.md`，`docs/sdk-contract.md` §3.2 #15 引用本文件，改名/移动须同步。
>
> **一句话结论**：`guanjin.authz.enabled` 默认 **`true`**（"开箱即判定"是默认姿态）；`authz.enabled=true` 而容器内**没有 `AuthzModel` bean** → **启动失败**，不静默降级为"不判定"。

## 1. 有明文的部分（基线原文）

| 事实 | 出处 |
|---|---|
| 接入时必须**声明权限模型**（`AuthzModel.builder()` 声明式模型，"必须"级能力） | `docs/baseline/GuanJin-SDK契约.md:72`（能力表第 13 项）+ `:282`「§4.2 ② 声明权限模型（Builder）」 |
| 接入示例就是一个 `@Bean public AuthzModel authzModel()` | `docs/baseline/GuanJin-SDK契约.md:287-292` |
| `false` = 不注册判定（等价未接入），**绝不是"全部放行"**；非 `local\|test` 置 `false` → 启动失败 | `docs/sdk-contract.md` §3.2 #1 **与** #15 的安全约束列（D6(4)：`enabled`/`authz.enabled` 的 profile 门控是**加固**，不进 CH） |

## 2. **基线无明文的部分（必须保留的诚实标注）**

> **「缺 bean → 启动失败」这个具体执行形态，基线没有明文**，它是**实现方定的形态**；基线有明文的只是"**必须声明 `AuthzModel` bean**"这一**接入步骤**（`GuanJin-SDK契约.md:287-292`）。

为什么选"启动失败"而不是"告警 + 不判定"：`authz.enabled=true` 是**默认值**，此时若不判定，等于让接入方以为在判定、实际全放行——这正是 `sdk-contract.md` §九「不存在生产可跳过验签/放行开关」要消灭的隐性降级（与 #1、#15 的 profile 门控同一条判据）。因此把"配置说开了、其实没模型"变成**启动即失败**，属**让已禁止状态可执行**（加固），不是新增契约面。

## 3. 为什么是「澄清」而不是「改契约」

| 判据（`decisions.md:379` 三分法） | 本条 |
|---|---|
| 新增 key / 改 key 名 | 否（仍 29 项，编号 1..29 连续） |
| 改默认值 | 否（仍 `true`） |
| 改必填性 | 否（仍「否」） |
| 让业务方能用基线**原本不允许**的方式配置 | 否——基线本就要求声明 bean；本条只是让"没声明"变成可执行失败 |

→ **不进 CH、不动判据文件、不动 90 项账目**。

## 4. 三语言等价（`sdk-contract.md:20/22` 的要求）

`sdk-contract.md:20`（22 条能力一个不多一个不少，三语言语义与判据一致）与 `:22`（三语言只允许打包物与宿主接入点两处差异，**fail-closed 必须逐字节一致**）意味着：

- **Java / Node / Go 都必须在装配期失败**（不是运行期第一次判定时才失败，也不是只在 Java 生效）。
- **现状**：仅有 Java 侧按此形态实现；**Go / Node 尚未实现同源等价检查 → 属待补缺陷**（已记入 `#55`/`#59` 的风险项）。补法不是"给某个语言开开关"，而是各语言在装配期做同一检查。

## 5. 硬边界

- **不加任何开关键**：`authz.require-model` / `authz.enabled` 之外的"允许无模型运行"开关一律不许出现——那等于给"实际不判定"开生产后门。
- 不动判据文件、不动 `migrations/`、不动 `go.mod`、不改任何代码（本文件只记录口径）。
- 报错文本必须**点名修法**（声明 `AuthzModel` bean，或仅 `local|test` 置 `authz.enabled=false`），不得只抛"缺少依赖"这类无行动指引的异常。
