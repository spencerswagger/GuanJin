**分支**：`fix/98-vuln-gate`（从 `origin/main` `7ff9b25` 起）

## 1. 为什么不能沿用 #98 的原方案（硬冲突，不是偏好）

#98 的门禁在 CI 里**在五处联网**：

| 点 | 依赖 | 后果（零网络 runner） |
|---|---|---|
| `go install golang.org/x/vuln/cmd/govulncheck@v1.1.4` | `proxy.golang.org` / 内网 GOPROXY | 装不上 |
| `curl trivy_*.tar.gz` + checksums | `github.com` releases | 下不来 |
| `govulncheck ./...` | `vuln.go.dev` 漏洞库 | 跑不起来 |
| `trivy fs` | `ghcr.io` 的 trivy-db | 跑不起来 |
| `--self-test` 里 `go mod tidy` | `proxy.golang.org` | 拉不到依赖 |

与本仓 runner 的实况（#125：`apt-get` 解析不到 `azure.archive.ubuntu.com`，退避 4 分钟后 `exit 100`，
后续 13 个 step 全 skipped；`skipped` 不是绿）**直接冲突**。两条路：
①把门禁降级成"跑不起来就跳过"——等于关掉门禁，不允许；
②把"数据获取"从 CI 里搬出去，CI 只做**本地可复算的判定**——本 PR 走这条。

## 2. 落地形态

| 物 | 作用 |

## 3. 判定口径（写死在引擎里）

| 生态 | 阻断 | 理由 |
|---|---|---|
| Go | **命中即红**（含 severity `-`） | Go 官方 OSV 不带 CVSS；离线数据无符号级可达性 → 坐标级命中即红 = **更宽，只多报不漏报** |
| npm | **HIGH/CRITICAL** 红；MODERATE/LOW 打 `[INFO]` | 判据原文阈值 |

fail-closed：快照缺失 / 无 `generated_at` / 过期 / 坏行 / 依赖版本不可解析 / lockfile 文本扫描与 JSON 条数不一致 /
白名单过期 / 白名单不再命中 / 白名单格式坏行 → 全部 `exit 1`。

## 6. 遗留与代价（不藏）

1. **新增依赖不会自动进快照**：动了 `go.mod` / `package-lock.json` 必须顺手跑一次
   `python3 scripts/vuln-snapshot-refresh.py` 并提交 diff。缓解：90 天过期即红 + `docs/qa/vuln-scan.md §3` 写死流程。
2. **`sdk/java` 仍未覆盖**（D23③ 第二段：2026-12-10 前改离线 SBOM，Nova 产 → Gate 判）。
3. **无符号级可达性**：离线方案是坐标级判定，比 govulncheck 宽（会多报），不会漏报本仓坐标上的公告；
   但"某条公告的代码路径是否真被调用"这种结论本闸给不出——需要时用 `govulncheck` 在**有网环境**人工复核。
4. **`AC-ENG-07` 记账**：判据原文写的是"govulncheck / trivy 必须真跑"。本实现改为"离线快照 + 本地判定"，
   口径与理由已写进 `docs/qa/vuln-scan.md §1`；**是否仍记 PASS 由 Gate / Spec 定**，本 PR 只提供实现与证据。
