## 2. 已生效的设计决定（速查）

| 维度 | 决定 |
|---|---|
| **产品性质** | 全新项目（greenfield）、独立仓库；只借鉴旧项目的设计，不继承代码 |
| **使用方** | 单租户；**运营方**是集团内部；**用户全部是 C 端** |
| **规模** | 100 个业务系统 / 千万级 C 端用户 / 峰值并发登录 200 QPS |
| **账号来源** | **开放自注册**；注册必带业务系统上下文，按目标业务系统的准入规则计算 |
| **合规目标** | 等保三级；**密评上限为二级**（因不引入硬件密码模块）；随接入的业务系统一起测评 |
| **因子** | V1 四类（密码 / 短信 / 邮箱 / TOTP）；**类型不设限、架构上无限扩充** |
| **档位** | **只有「客户端档位」一层**（= 访问该业务系统的准入门槛）；**默认 L2，承诺 AAL1**（要等保三级须显式选 L3）；平台级实现全部按最高固定 |
| **无上下文时的判定** | 按该用户**已访问过的业务系统中档位最高的那一个**（生效配置） |
| **权限** | 平台**不定义**授权策略；平台管「用户 → 角色」绑定与审计，业务方管「角色 → 权限」定义与判定；**判定在 SDK 本地** |
| **数据面形态** | **关津承载数据面，代替独立网关**；且为**薄数据面** —— 只做依赖认证语义的 7 件事，TLS 终结 / WAF / 负载均衡 / 灰度 / 熔断**前置给 nginx 或 Kong** |
| **部署形态** | **多副本 + 无状态化**（承载数据面后必须水平扩展）；挑战落库、Redis 只承载限流计数与热缓存 |
| **撤销** | 承载数据面形态下**实时生效**，无需撤销清单传播 |
| **服务间认证** | 应用层签名。**关津 → 业务系统用 SM2 非对称签名**（一方签多方验，密钥管理最简）；**业务系统 → 关津用每系统独立 secret 的 HMAC** |
| **身份注入** | **单个签名 header**（`X-GuanJin-Assertion`，逐请求签发、有效期极短、独立密钥对经 JWKS 发布）；SDK 验签后**必须剥离** |
| **用户访问令牌** | **JWT（`SM3withSM2` 签名，含 `kid`）**；`/userinfo` 本地解析；`/oauth/introspect` 仅限低频、**禁止每请求校验** |
| **挑战（验证码）** | **权威状态落数据库**（`challenges` 表），Redis 只承载限流计数与热缓存 |
| **密钥与算法** | 主密钥环境变量注入、不落库；口令派生 PBKDF2-SM3；审计完整性 HMAC-SM3；敏感字段 SM4；**均固定为最高级** |
| **后端数据访问** | **GORM** + 五条硬约束（禁软删除、禁 `AutoMigrate` 上线、唯一约束冲突映射业务错误码、复杂查询走 `Raw()`、高频表批量写） |
| **SDK 版本** | **只出 Spring Boot 2.x（javax）产物**；拆 `guanjin-core`（零 Spring 依赖）+ `guanjin-spring-boot2`（适配层） |
| **C 端个人中心** | **全量**：改密 + 换绑 + 在线会话与踢设备 + 账号注销 + 数据导出 |
| **令牌签名算法** | **`SM3withSM2`（全链路国密）**。密评明确要求签名必须国密、禁止与 SHA 系列混用（属一级高风险项），故不采用国际算法（RSA/SHA 系列） |
| **传输加密** | v1 用**标准 TLS**；**国密 TLS（SM2 证书 / TLCP）仅预留、v1 不启用**。⚠️ **不启用国密 TLS 则密评不通过**（密评要求传输、存储、认证、签名、校验全链路国密），属部署前置项 |
| **密钥轮换与历史审计** | 主密钥轮换后，用于验证历史审计链的旧密钥副本**保留与审计留存期相同（365 天）**，之后归档 |
| **SDK 协作形态** | **只保留网关形态**（流量必过数据面）；不提供"业务系统直连"的兜底模式 |

## 4. 仍未确定的事项

### 4.1 需人工裁决

**当前无。** 全部未定项均已在 §4.2 给出默认取向，实现时按默认走即可。

### 4.2 有默认值，实现时按默认走

| # | 事项 | 默认取向 |
|---|---|---|
| 1 | `users.username` 与标识符记录的关系 | `users.username` 为权威登录名；V1 不为它另建 `identifiers` 行 |
| 2 | 失败计数/锁定状态的权威位置 | Redis 为实时权威（原子 INCR + fail-closed），`authenticators` 的 `fail_count/locked_until` 为持久化镜像 |
| 3 | "至少 1 个可用认证器"与"仅信道型注册"的边界 | 可用认证能力 = 持有型认证器 ∪ 已验证的认证型标识符 |
| 4 | `sessions.client_id` | NOT NULL（登录必有业务系统上下文） |
| 5 | `identifiers.value` 的存储 | 盲索引（HMAC-SM3）+ `value_enc`（SM4）+ `value_masked` 三段式——同时满足唯一约束与加密落库 |
| 6 | `employee_no` 标识符类型 | 保留取值，标注"管理侧录入型"，V1 可不启用 |
| 7 | `is_primary` 的唯一范围 | 每用户唯一 |
| 8 | 首次从未访问过任何业务系统时的"生效配置" | 回退到平台默认 L2（→ AAL1） |
| 9 | `jti` 防重放的存储 | 多副本下必须用 Redis |
| 10 | `user_visited_clients` 由谁写 | 由数据面写（SDK 不参与） |
| 11 | 回调地址白名单谁校验 | 平台侧统一校验（SDK 不登记） |
| 12 | 审计表分区与留存清理 | 按月分区 + `DROP PARTITION` 整段清理（365 天） |
| 13 | UUID 生成 | 应用层生成 UUID v7（不要求 PostgreSQL 18） |
| 14 | Flow Descriptor 字段 | 以 `页面规格` §4.1 的结构为契约冻结 |
| 15 | 档位 → ACR 映射 | L1/L2 → AAL1；L3 → AAL2；`amr` 组合按因子能力声明的 `achievable_acr` 计算 |
| 16 | 门槛项的存储位置 | 门槛项落 `login_policies`；`clients` 只存 `tier` |
| 17 | 三员角色与 7 种"角色"的关系 | 三员（系统管理员 / 安全管理员 / 审计员）是**平台管理面**的鉴权角色；7 种是"使用者角色"，不进平台鉴权 |
| 18 | 数据面 route → client 的映射 | V1 按域名 / 路径前缀静态映射；映射关系留抽象，便于将来接服务发现 |
| 19 | 审计哈希链的写序与形态 | 单全局链 + `pg_advisory_xact_lock` 串行化链尾；预留分链演进 |
| 20 | 签名算法的可替换边界 | 签名 / 验签走独立 SPI，算法可替换（不写死） |
| 21 | `/admin/policies` 与客户端配置的编辑归属 | 保持"策略页只读 + 客户端页编辑"，单一编辑入口避免双写 |
| 22 | 多语言 | 预留 i18n 结构，v1 只做中文 |
| 23 | JWKS 路径与 SM2 公钥表示 | 路径用 `/.well-known/jwks.json`（OIDC 惯例）；SM2 公钥用 `kty:"EC"` + `crv:"SM2"`，用 `kid` 前缀区分"用户令牌 / 网关内部令牌"两类密钥 |
| 24 | 角色如何到达 SDK | **放进内部令牌**（方案 A，零回源）；`/api/v1/agent/policies` 拉取作为兼容可选项 |
| 25 | `AuthzModel.builder()` 的完整签名 | `role(name).can(resource, ...actions)`、`role(name).withClearance(level)`、`resourceGroup(name).contains(resource)`、`defaultRole(name).can(...)`、`build()` |
| 26 | Agent 面 HMAC 的规范 | HMAC-SM3；canonical 串 = `method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + sha256(body)`；时间戳窗口 ±300s；nonce 落 Redis 去重 |
| 27 | 权限与密级数据的完整性校验 | 加载策略数据时校验完整性标签，失败即 fail-closed |
| 28 | 分页 / 幂等 / `trace_id` | 分页用 `limit`+`cursor`；写操作支持 `Idempotency-Key`；`trace_id` 贯穿日志、`auth_events`、`audit_logs`（以 `接口清单` §5 为正式约定） |
| 29 | 默认角色名与默认权限点 | **由 SDK 接入方把控** —— 平台不预设角色名与权限点，只要求"权限尽量小、不得是'已登录即可访问全部'"；接入方通过 `AuthzModel.builder().defaultRole(name).can(...)` 声明并随策略快照上报 |
